# Starter code review

Function names refer to the supplied starter. Examples below are inspection-based illustrations, not executed regression tests. The documented fixes were reviewed against the implementation in `app/main.py`; the limited manual checks and their evidence are recorded in README's verification section. Those checks do not verify every fix below.

| # | Where | What is wrong | Example input or symptom | How it is fixed |
|---|---|---|---|---|
| 1 | `health` | Always reports readiness without contacting MongoDB. | An unavailable database still produces 200. | Ping MongoDB and return 503 on database failure. |
| 2 | Startup, `create_employee`, `punch_in` | No application indexes; read-then-insert duplicate checks are not atomic. | Concurrent identical requests can both insert, while large queries lack useful indexes. | Create named indexes idempotently; unique employee and attendance keys enforce concurrency guarantees, with duplicate-key errors translated to 409. |
| 3 | `EmployeeIn` | Omits contract validation for codes, email, lengths, shifts, equal shift times, and actual calendar dates. | `emp_code="abc"`, empty name, `shift_start="25:70"`, or `joined_on="2026-02-30"` is accepted. | Add exact formats, length bounds, calendar validation, and unequal-shift validation for creation. |
| 4 | `create_employee`, `punch_in` | Uses naive host-local datetimes, which MongoDB treats as UTC; attendance dates also depend on the host zone. | An IST host stores local creation time as UTC; a UTC host misdates a 00:15 IST punch. | Use aware UTC instants for storage and explicitly convert to IST for calendar rules. |
| 5 | Response construction | Returns datetimes as ISO strings instead of integer epoch milliseconds. | `created_at` and `punch_in` have the wrong HTTP types. | Serialize every instant to epoch milliseconds, including nested correction history. |
| 6 | `PunchInIn`, `punch_in` | Does not enforce strict timestamp types/ranges and treats zero as an omitted timestamp. | A numeric string or seconds-looking integer may pass; zero becomes now. | Require bounded integer milliseconds, reject booleans/floats/strings/null, and distinguish omission from supplied values. |
| 7 | Punch handling and helpers | Does not truncate instants to whole seconds before storage and calculation. | A `.900` fraction survives in the stored timestamp and can change duration rounding. | Truncate boundary instants and consistently calculate with the truncated values. |
| 8 | `list_employees` | Uses `skip = page * page_size`. | Page 1 skips the first 20 employees by default. | Use `(page - 1) * page_size`. |
| 9 | `list_employees` | Counts the entire collection despite the department filter. | A department with 3 employees reports company-wide headcount as `total`. | Reuse the item query's filter for the count. |
| 10 | Both list endpoints | Employee ordering is missing; attendance ordering lacks the employee-code tie-breaker. | Results depend on insertion order, especially records sharing a date. | Sort employees by code; sort attendance by date descending, then code ascending, in MongoDB. |
| 11 | Both list endpoints | Pagination bounds are not validated. | `page=0`, negative values, or `page_size=1000` is accepted or causes database errors. | Require page >= 1 and page size between 1 and 100. |
| 12 | `punch_in` | Dereferences an unknown employee. | `emp["shift_start"]` raises an error when the lookup returns null. | Return 404 before accessing employee fields. |
| 13 | `PunchInIn` | Accepts arbitrary statuses, including absence statuses. | `status="LEAVE"` creates a record with a punch-in. | Restrict punch-in to `PRESENT`, `WFH`, and `ON_DUTY`. |
| 14 | `punch_in`, shift helpers | Ignores the overnight attendance-day exception; shift start/end calculations use the wrong calendar day. | A 02:00 punch for a 22:00-06:00 shift belongs to the previous day; the shift end is the following morning. | Derive the attendance date in IST and construct aware shift boundaries from that date, advancing overnight shift end. |
| 15 | `compute_late_minutes` | Floors minutes before checking the 10-minute grace boundary. | A 09:40:01 punch for a 09:30 shift incorrectly returns 0 instead of 10. | Compare elapsed seconds with 600 first, then floor the minutes if late. |
| 16 | `compute_work_hours` | Uses binary floating-point and ties-to-even `round`. | 1 hour 7 minutes 30 seconds is 1.125 hours and must round to 1.13. | Divide with `Decimal` and round with `ROUND_HALF_UP`. |
| 17 | `compute_overtime` | Counts overtime below 30 minutes and can subtract naive and aware datetimes. | Five minutes after shift end returns 5 instead of 0; naive punches can raise `TypeError`. | Normalize timestamps and count floored overtime only when it reaches 30 minutes. |
| 18 | `punch_in`, `list_attendance` | Exposes an attendance `id` derived from internal `_id`. | Responses include an identifier prohibited by the contract. | Serialize contract fields only and address records by `(emp_code, date)`. |
| 19 | `list_attendance` | Loads all matching documents, sorts, and slices in Python. | One requested page can load 100,000 documents into application memory. | Apply indexed filter/sort/skip/limit in MongoDB and count with the same filter. |
| 20 | `list_attendance` | Does not validate date formats, actual dates, reversed ranges, or statuses. | `date_from=2026-07-20&date_to=2026-07-01` or `status=UNKNOWN` fails to return 422. | Validate values and range order before querying. |
| 21 | Optional list filters | Uses truthiness rather than checking whether a filter was supplied. | `department=` silently lists all departments instead of matching exactly. | Apply supplied optional filters using `is not None`. |
| 22 | `list_attendance` | Omits required defaults for legacy records. | The supplied legacy document returns no `history` or `half_day`. | Normalize missing history, half-day, late/overtime, and nullable attendance fields when serializing. |
| 23 | Missing punch-out endpoint | Cannot close attendance, enforce duration bounds, or protect simultaneous punch-outs. | The documented request has no implemented route. | Find the latest qualifying punch-in, validate duration, derive final values, and conditionally update; concurrent losers receive 409. |
| 24 | Missing correction endpoint | Cannot recompute corrected records or preserve an audit trail. | The documented PATCH has no route. | Validate final status/times, reject unchanged requests, recompute derived fields, and append one changes-only history entry with an atomic snapshot-conditional update. |
| 25 | Missing employee monthly analytics | Cannot report working days, weighted presence, leave, lateness, overtime, or attendance percentage. | The monthly summary request has no route. | Aggregate stored values; account for joining dates in working days, weekday-only presence, half days, empty results, and half-up rounding. |
| 26 | Missing department summary | Cannot report inclusive headcount or record-weighted work hours. | Zero-log employees have no available summary representation. | Start with employees eligible by month-end and look up grouped logs; preserve each person's headcount and average qualifying records. |
| 27 | Missing late leaderboard | Cannot implement competition ranks and cutoff ties. | Totals 60, 30, 30, 10 require ranks 1, 2, 2, 4; limit 2 returns three employees. | Join employee metadata, ignore orphan logs, filter departments before `$rank`, then retain `rank <= limit` and order ties by code. |
| 28 | Missing department trend | Cannot fill missing days, compute daily headcounts, or calculate the requested moving average. | A weekend or log-free day must still produce one row. | Generate the calendar inside MongoDB, join counts, calculate nullable rates, and use a seven-row window bounded by the requested range. |
| 29 | Missing admin explain endpoint | Cannot inspect the actual endpoint operations. | The documented explain request has no route. | Reuse query/aggregation builders and request `executionStats` with the same filters, ordering, pagination, and index hints. |

## Reviewed choices that are not defects

- Employee codes are the correct public identifiers. Attendance uses `(emp_code, date)`, not an ObjectId reference.
- Calendar dates and shift times correctly remain strings. Actual instants correctly belong in MongoDB as BSON dates; integer milliseconds are their HTTP representation.
- `load_dotenv()` preserves real environment variables by default, as required. A local `.env` is permitted but must not be submitted.
- Ignoring extra request fields is appropriate for read-only derived values, which must be computed rather than accepted from the client.
- Punch-in correctly initializes null punch-out/work hours, zero overtime, false half-day, and empty history. Original punches must not append correction history.
- Missing records must not become synthetic `ABSENT` documents. Analytics must read authoritative stored derived values, including values in seeded data.
- The supplied route names, default shift times, and single-file application layout are retained.
